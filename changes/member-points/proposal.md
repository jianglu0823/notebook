# 会员积分账号体系(member-points)

## Why

产品已有伴侣、小世界、创作、问答等大量 LLM 场景,Qwen/DashScope 等付费模型的 token 消耗是真金白银,目前完全没有用量计量与成本控制手段:用户可无限调用付费模型,平台无法观测单人成本、无法限额、无法商业化。`ChatCompletion` 已返回 input/output token,`ChatModelFactory` 已配各模型单价,计量条件成熟,缺的是账户体系。本变更建立以积分为统一计价单位的会员账号体系:按 token 用量扣减积分、账户流水可追溯、日终清算对账,并以充值和运营赠分形成商业闭环。

## What Changes

- 新增积分账户:每个用户一个额度账户(余额 + 累计充值 + 累计消耗),注册自动开户。
- 新增计量扣费:所有 LLM 调用点按实际 token 用量 × 模型单价折算积分扣减;付费模型按真实单价,GLM 免费通道按极低名义费率扣减(防滥用);余额不足拦截所有 LLM 调用,免费模型费率极低,日常签到赠分可覆盖基本使用。
- 新增账户流水:每笔变动一条流水(类型/金额/余额快照/关联业务单号),支持分页查询。
- 新增日终清算:每日对账流水合计与账户快照,差异告警,重算校准。
- 新增充值体系:套餐档位 + 充值订单 + 兑换码/人工到账(在线支付通道预留接口)。
- 新增运营规则:注册赠分、每日签到、邀请返利、活动赠分,规则配置化。
- 新增会员等级:按累计充值分级,等级权益为消耗折扣率与赠分倍率。
- 前端(App + 网页)新增"我的积分"页:余额、流水、充值、签到入口;余额不足时给出引导。

## Scope

### In

- 积分账户、流水、余额校验与扣减(含预冻结-实结)
- token 计量接入全部 LLM 调用点(伴侣/小世界/创作/问答/生成/语音)
- 日终清算对账与差异告警
- 充值套餐、订单状态机、兑换码充值、管理端人工到账
- 运营赠分规则(注册/签到/邀请/活动)与会员等级权益
- App 与网页的积分页、余额不足提示

### Out

- 微信/支付宝在线支付通道对接(订单模型与接口预留,下迭代接)
- 退款与提现
- 企业多成员共享账户
- 积分转赠与交易市场
- 发票与税务

## Impact

- **后端新模块**:`io.llmnote.points`(账户/流水/清算/充值/规则/等级),新增 6-8 张表。
- **横切改动**:全部 LLM 调用点接入计量拦截,以 `ChatCompletion`/`ChatModelFactory` 为统一入口收口,避免逐点散落。
- **既有模块**:auth(注册开户钩子)、llm(单价读取、计量上报)、schedule(日终清算定时)、log(计费相关访问日志)。
- **前端**:App `me/` 新增积分页;网页 `index.html` 我的面板加积分区块;PricingController 费用换算读账户余额。
- **兼容性**:存量用户一次性初始化账户并发放启动赠分;不破坏现有 API 契约,仅新增余额不足错误码。

## Capabilities

- `points-account`:积分账户、流水、余额查询、开户
- `points-metering`:token 计量、扣减、预冻结-实结、余额不足拦截、免费模型低费率
- `points-settlement`:日终清算对账、差异告警、校准
- `points-recharge`:充值套餐、订单、兑换码、人工到账
- `points-growth`:运营赠分规则(注册/签到/邀请/活动)、会员等级与权益
